# Simplicity Review Guide

A concise reference for reviewing whether software is easy to understand, change, and verify. Simplicity is not minimal line count: it is the absence of unnecessary concepts, coupling, and work.

## Review path

1. [Purpose and value](the-driving-forces-of-software-design.md)
2. [Designing for change](change.md)
3. [Small, evidence-based changes](the-future.md)
4. [Simple code](simplicity.md)
5. [Controlling complexity](complexity.md)
6. [Testing behavior](testing.md)

## How to use this collection

Start with the user problem and the value of the change. Then inspect its maintenance cost, scope, concepts, dependencies, and verification. Report concrete consequences rather than aesthetic preferences. Prefer the smallest well-supported change that leaves the system easier to work with.
